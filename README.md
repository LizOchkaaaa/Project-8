# Тема 8. Безопасная сборка и выпуск приложения

### Проблема
Приложение может быть опубликовано с уязвимостями или опасными настройками.

### Основное задание
1. Разработать автоматизированный процесс проверки, сборки
и развертывания небольшого приложения.
2. Реализовать не менее трех видов проверок безопасности и
запретить выпуск при обнаружении критических проблем.
3. Обосновать состав и последовательность проверок. 
4. Провести тесты: добавить учебную ошибку, показать отказ в выпуске и успешное
прохождение после исправления.

### Дополнительное задание – ИИ-агент
Разработать помощника, который получает отчеты неуспешных проверок, объединяет связанные замечания и предлагает
разработчику порядок исправления ошибок.


# 🛡️ DevSecOps CI/CD Pipeline & AI Security Assistant

Веб-приложение "Заметки" на базе **Flask** с интегрированным конвейером CI/CD в **GitHub Actions** и **ИИ-агентом** для анализа уязвимостей.

---

## Архитектура проекта

Пайплайн автоматически запускается при каждом `push` и `pull_request` в ветку `main` и состоит из 8 этапов:

| Этап (Job) | Инструмент | Назначение                                                                                    |
| :--- | :--- |:----------------------------------------------------------------------------------------------|
| **Lint** | `Ruff` | Проверка стиля кода и форматирование.                                                         |
| **Secret Detection** | `Gitleaks` | Поиск закоммиченных токенов, паролей и API-ключей в истории Git.                              |
| **SAST** | `Bandit` | Статический анализ исходного кода Python на наличие уязвимостей.                              |
| **SCA** | `pip-audit` | Проверка зависимостей из `requirements.txt` по базам известных уязвимостей (CVE).             |
| **Tests** | `pytest` + `Allure` | Юнит-тестирование бизнес-логики и проверка HTTP-заголовков безопасности.                      |
| **Build** | `Docker Buildx` | Сборка Docker-образа приложения и сохранение его как артефакта.                               |
| **Container Scan** | `Trivy` | Сканирование собранного Docker-образа на уязвимости уровня ОС и пакетов (`CRITICAL`, `HIGH`). |
| **DAST** | `OWASP ZAP` | Динамическое тестирование запущенного контейнера (Baseline Scan).                             |

---

## Дополнительное задание: ИИ-агент

Для ускорения разбора падений пайплайна разработан ИИ-помощник (`ai-agent/security_agent.py`), который автоматически запускается при провале любого из этапов проверки CI/CD.

### Принцип работы агента:
1. **Сбор и нормализация данных:** Агент скачивает JSON-артефакты всех завершенных проверок (`pytest.json`, `sast.json`, `sca.json`, `image.json`, `report.json` от OWASP ZAP), отфильтровывает избыточную техническую информацию и извлекает суть ошибок (название правила, файл/URL, критичность, фрагмент стектрейса).
2. **Корреляция и группировка:** Очищенный JSON передается в модель (`DeepSeek V4.1 Flash` через OpenAI-совместимый API) с промптом.
3. **Визуализация и формирование отчета:**
    * Формирует Markdown-отчет на основе шаблона `ai-agent/report_template.md`.
    * Сохраняет итоговый файл `ai-report.md` в **Artifacts** для скачивания.

