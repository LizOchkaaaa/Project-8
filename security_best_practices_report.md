## Обязательные исправления исходного приложения

1. **P1 — отсутствующий шаблон главной.** В PR № 3 `app/main.py:32` вызывал `render_template("index.html")`, но файла не было: GET `/` давал 500. Добавлены [шаблоны](app/templates/index.html), регрессия проверяется существующим `test_index`. Без исправления приложение и DAST попадали в ошибку сервера.
2. **P1 — удаление неверной заметки.** В PR № 3 `app/main.py:58` создавал ID через `len(items)+1`; после create/create/delete-first/create два объекта получали один ID. DELETE удалял старую запись вместо выбранной новой. В [create_item](app/main.py#L50) теперь счётчик под тем же lock; [регрессионный тест](tests/test_regressions.py#L8) проверяет оставшийся текст.
3. **P2 — непредсказуемое состояние между workers.** В исходном Dockerfile запускались два процесса с отдельными списками. POST в A не был виден в B. Для учебного in-memory режима [Dockerfile](Dockerfile) теперь запускает один worker. Перезапуск по-прежнему стирает записи; для постоянных данных потребуется хранилище.
4. **P2 — pytest из корня не импортировал app.** При переносе был удалён pytest.ini. [Корневая конфигурация](pytest.ini) восстановлена; `pytest` и `python -m pytest` проходят одинаково.

## Обязательные исправления исходного CI

5. **P1 — проверки не доходили до сборки.** PR № 1 включал pip cache в lint без установки pip-зависимостей; реальный post-step завершался ошибкой отсутствующего каталога. Пути ориентировались на первоначальный каркас: пустой requirements давал формальный успех SCA без проверки приложения. [Новый workflow](.github/workflows/ci.yml) использует корневые manifests, lint не включает этот кэш.
6. **P1 — несуществующий ref Trivy.** `aquasecurity/trivy-action@v0.76.2` отсутствует. Заменён проверенным `@0.35.0`, версия самого Trivy задаётся отдельно. Существование refs и images проверено по официальным источникам; это не runtime-проверка контейнера.
7. **P1 — критическая CVE без исправления могла не блокировать выпуск.** PR № 1 включал `ignore-unfixed: true`. Теперь [настройка](.github/workflows/ci.yml#L188) не исключает такие находки; [policy](.security/policy.yml) блокирует critical/high/unknown.
8. **P2 — readiness пропускал HTTP 404.** YAML сворачивал строку с обратным слешем так, что `--fail` становился другим аргументом. Исправленная [команда](.github/workflows/ci.yml#L218) проверена из разобранного YAML: 200 → exit 0, 404/500 → exit 22.
9. **P1 — отсутствовал явный выпуск после полного допуска.** В исходном CI не было deploy и исполняемой policy. Добавлены [security-gate](.github/workflows/ci.yml#L240) с проверкой всех обязательных jobs и [deploy](.github/workflows/ci.yml#L303) того же image artifact после gate. Стенд временный, в runner; публичный хостинг не заявляется.

## Независимое ревью помощника

Прочитан весь поток CLI → парсеры → policy/группировка → модель → JSON/Markdown → браузер, а также тесты и DAG workflow. Новых подтверждённых блокирующих дефектов в этом потоке при локальном ревью не обнаружено.

- [read_reports](security_assistant/parsers.py#L262) проверяет структуры пяти форматов, размеры и число записей. Missing/invalid/operational failure не превращается в clean. Неизвестная критичность блокируется.
- [evaluate](security_assistant/policy.py#L32) не использует модель. При полном CI gate дополнительно проверяются результаты lint/tests/scanners/build. Локальный reports-only режим явно ограничен.
- [group_findings](security_assistant/policy.py#L73) сохраняет первичные ID и occurrences, объединяет aliases только для одинакового компонента/версии/ecosystem. Тестируются мосты aliases и разные пакеты.
- [endpoint](security_assistant/model.py#L24) получает URL только из доверенной конфигурации, требует HTTPS за исключением loopback HTTP. Redirect отключён; реальный локальный тест 307 подтверждает отсутствие пересылки Bearer на redirect target.
- [recommend](security_assistant/model.py#L138) ограничивает вход/ответ и таймаут, передаёт allowlist полей, не отправляет Secret/Match/код/пути/описания. Отказ модели и неправильный ответ дают явно помеченный fallback без сырых исключений.
- [validate_response](security_assistant/model.py#L95) требует полный набор известных IDs, уникальный порядок и ограниченные строки. Модель не может понизить приоритет, удалить критическую группу или поменять gate. Совет никогда не исполняется.
- [security.js](app/static/security.js) читает analysis.json через File API и выводит значения через textContent. XSS-строки остаются текстом; после выбора файла нет сетевых запросов. Есть лимиты и сброс устаревшего результата при ошибке импорта.

Из практических доработок после ревью добавлены [.env.example](.env.example) без секретов и инструкция ввода ключа через защищённый prompt PowerShell. CLI читает только окружение, не загружает .env автоматически.

## Фактические проверки

- Независимый повтор: **60 passed** в обоих вариантах pytest; Allure коллеги сохранён. Проверены ID/delete, шаблоны, лимиты, пять парсеров, группировка, gate и mocked API success/401/429/timeout/invalid JSON/IDs/redirect.
- Ruff lint/format, JS syntax, actionlint и `git diff --check`: пройдены. ShellCheck в actionlint недоступен; health shell-команда проверена отдельно.
- Bandit: 0 medium/high, один LOW B404 — импорт subprocess в безопасном demo-скрипте. Политика не скрывает эту находку и разрешает LOW.
- pip-audit: 8 runtime зависимостей, 0 известных уязвимостей в полученном ответе. Повтор локального набора использовал сохранённый ответ аудита, не выдавался за обновление CVE-базы.
- Gitleaks 8.30.0: реальная локальная проверка истории (5 commits) и рабочего дерева; утечек не найдено. Официальный Windows binary проверен по опубликованному SHA256; отчёты сохранены с редактированием секретов.
- Headless UI: создание/чтение/удаление, локальный импорт, malformed/oversized input, XSS, клавиатура, reduced motion и темы на 360/1100 px. Визуально просмотрены страницы; минимальный измеренный контраст текстовой палитры 6.17:1.
- Реальный учебный Bandit: B602 HIGH → **BLOCK**; после удаления опасной функции → **PASS**. Код ошибки не исполнялся. Четыре остальных отчёта этого demo синтетические и помечены; это не сквозной remote release.

## Остаточные ограничения

1. Docker/Trivy/ZAP, Linux Gunicorn, полный remote Actions/deploy и реальный API выбранного пользователем провайдера не подтверждены локальными проверками. Нельзя утверждать, что полный pipeline уже зелёный.
2. Workflow запрещает deploy при плохом gate. Административный запрет merge требует required check в branch protection; эта настройка владельца не изменялась.
3. ZAP baseline пассивен, не заменяет полный аудит API. Разрешённые форматы сканеров закреплены; несовместимое изменение формата закроет допуск до обновления парсера.
4. Заметки — общий учебный сервис без авторизации, для несекретных временных данных. Импортированный analysis.json не удостоверяет происхождение результата. Постоянный production-хостинг не настроен.
5. Context7 не был подключён. API и action refs сверялись с официальными исходниками; вызовы Context7 не заявляются. Graphify использовался локально в режиме code-only, выводы подтверждены чтением кода.

Итог: локальные изменения пригодны для PR и проверки в CI. Одобрение исходного PR № 1 без исправлений и заявление о завершённом полном выпуске не обоснованы.
